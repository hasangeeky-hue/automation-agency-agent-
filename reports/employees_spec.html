The argument

Why eighteen is the correct number

Difference 1 says an employee owns a lane end to end. The wireframe draws Inventory Controller, Pricing Analyst, Merchandiser, Promotions Manager and Lifecycle Analyst. Build those as five agents and nobody owns commerce. You get five task-doers handing work back, which is the exact thing the doctrine calls an agent, not an employee.

Difference 2 breaks too, and it breaks worse. Five agents means five separate memories. A promotion that lifted margin is simultaneously a pricing lesson, a merchandising lesson and a lifecycle lesson. Split across five playbooks, each one learns a fifth of the truth and none of them compounds. One Commerce Analyst reading one playbook gets sharper every week.

So the five commerce desks stay on screen exactly as drawn. They are five windows onto one worker, and each window says whose desk it is. You see one salary doing five jobs instead of imagining five salaries.

One entry on the wireframe is not an employee at all. The Orchestrator is your engine. It is the machine that runs the loop, holds the gates and advances the jobs. The wireframe draws it as something you can talk to, and that is right, but it never gets a daily report because it is not staff.

Cost, stated plainly. A roster entry is free. Money is spent by LLM calls inside job steps and by paid API calls, and by nothing else. The Integrations Engineer shipped this week runs every day for $0 because it is pure code with no model call. Adding desks costs nothing; adding paid steps costs money.

What every one of them owes you

The daily report

Difference 4 is the survival feature, so it is not optional per employee and it is not a log. Each of the eighteen answers the same three questions, every day, in the same shape:

  • Finished: work that actually completed, credited to the step that did it. The producer is never blamed for the publisher's failure.
  • Couldn't: and always with the cause. A failure with no reason recorded is treated as a bug in the engine, not as an acceptable answer.
  • Needs you: split in two, and never merged. A decision is your approval waiting. Blocked is a broken tool. Counting an outage as a pending approval is how an outage hides inside a to-do list for a week.

The gates are not settings. Spend, publish, send, deploy and cross-module command are permanent. Autonomy controls may add gates and can never remove one. No employee above has a code path that bypasses them, and the deploy check fails the build if one appears.

Roster, badges, tool slots and justifications in this document are read from content_engine_roster.py as it stands today, not from the wireframe's illustration data.
